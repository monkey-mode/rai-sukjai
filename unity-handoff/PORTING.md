# ไร่สุขใจ (Rai Sukjai) → Unity: porting guide

This folder is the hand-off from the web game (this repo) to the Unity version (target: **mobile**, Android and iOS).
It is generated by `node tools/export-unity.mjs` from the running web game, so it matches what the game draws.
Re-run it whenever new art is approved, then copy the changed sprites into the Unity project.

The web game stays the **reference**: when in doubt about a rule, a position or a look, play it, read its code, and
compare with the `Scenes/*_reference.png` renders.

---

## 1. What is in here

| Path | What |
|---|---|
| `Sprites/<category>/<id>.png` | Every sprite the web game uses, at **2× game size**. |
| `Sprites/<category>/<id>_n.png` | Its normal map (OpenGL convention: green = up), same size. Only the style-v3 art has one. |
| `sprites.json` | Per sprite: file, normal map, size, **pivot** (the ground point it stands on), `gameScale` (the size chart), footprint, height, tags, style (`flat-v3` = the new style, `legacy` = old art still to be redone). |
| `Scenes/farm.json`, `pen.json`, `market.json`, `village.json` | `placed`: every sprite exactly as the web game draws it, back to front: id, anchor position, scale (size chart included), flip. `layout`: the grid data the scene is built from (recipes, spots, plots, grass, rice, fences, lamps). |
| `Scenes/<scene>_reference.png` | The scene as the web game draws it today (1400×600; the 800×600 safe area starts at x = 300). |
| `Scenes/<scene>_codedrawn.png` | Only what the web game draws in code, not from sprites (2×): the farm's raised yard and field bunds, the forest floor behind the trees, and the soft contact ellipses under sprites. Rebuild these in Unity (sprites, a mesh, or bake this image). |
| `Data/config.json` | All game rules: crops, prices, growth, energy costs, ducks, seasons (`js/logic/config.js`). |
| `Data/daylight.json` | Time of day: tint, sun direction, lamp strength and shadow shape for every half hour 05:00–21:00. |
| `Data/size_chart.json` | The size chart and every asset's game scale. |

The **market and village** are not built in the new style yet: their kit pieces are being painted (`kit.shophouse_*`,
`kit.stall_*`, `kit.map_*`, `ground.market`, `ground.village`). `market.json` and `village.json` already hold their
new layouts in `layout` (the web game still draws the old art, so `placed` shows the old scenes). Re-export when
the art lands.

## 2. Project setup (Unity 6 LTS, "Universal 2D" template)

- **Platform:** Android and iOS. Landscape only. Reference resolution **800 × 600** game px for the safe area. The
  scenes are 1400 px wide, so wide phones (19.5:9 and wider) show the bleed on both sides instead of black bars.
- **Camera:** orthographic. With 1 unit = 100 game px, an orthographic size of **3** shows the 600 px height.
  Zoom by changing the size; clamp panning to the 1400 × 600 scene.
- **Sorting:** Project Settings → Graphics → Transparency Sort Mode = **Custom Axis (0, 1, 0)**, so lower sprites draw
  in front. Every pivot is the sprite's ground point, so y-sorting works. Put multi-part objects (a stall plus its
  vendor plus its counter, the buffalo) in a **Sorting Group**.
- **Sorting layers, back to front:** `Ground`, `GroundCover` (grass, rice), `World` (y-sorted), `Overlay` (labels,
  selection, floating text), `UI`.

### Sprite import (all of `Sprites/`)

| Setting | Value |
|---|---|
| Texture Type | Sprite (2D and UI) |
| Pixels Per Unit | **200** (the PNGs are 2× game size, so 1 unit = 100 game px) |
| Pivot | Custom: the `pivot` from `sprites.json` (an editor script can apply them all) |
| Mesh Type | Tight (Full Rect for the big ground layers) |
| Filter Mode | Bilinear |
| Generate Mip Maps | Off |
| Compression | ASTC 6×6 (Android and iOS); ASTC 4×4 for the characters and icons |
| Max Size | 4096 for `ground.*` and `bg.*` (2800 × 1200), 2048 for the rest |
| Normal map | Add `<id>_n.png` as the sprite's **Secondary Texture named `_NormalMap`** (Sprite Editor → Secondary Textures). Import the `_n.png` files as Texture Type **Default**, sRGB **off**. |

Pack everything except the grounds into **Sprite Atlases**, one per scene plus one shared, so each scene draws in a
handful of batches. Their normal maps go into the atlas's secondary texture automatically.

### Fonts

The UI uses **Kanit** (headings, numbers) and **Sarabun** (body), both Google Fonts. Make TextMeshPro font assets
with the **Thai** character range (U+0E00–U+0E7F) plus Basic Latin and ฿, using SDF and a 4096 atlas. Thai needs
correct mark placement: test the words ผักบุ้ง, ไข่, ป้าแดง, ลุงมี.

## 3. Coordinates

Web scene px: **x right, y down**. The 800 × 600 safe area spans x 0…800; the bleed runs to −300 and 1100.

```
Unity position = (x / 100, −y / 100)      // then move the camera to (4, −3) to centre the safe area
```

Each scene has its own isometric grid (2:1, tiles 64 × 32 px). `layout.grid.formula` gives it, for example
farm: `x = 290 + (gx − gy)·32, y = 226 + (gx + gy)·16 − z`. Put that in one `IsoGrid` helper per scene, with
`ToWorld(gx, gy, z)` and `ToGrid(worldPos)` for taps.

**Placement scale.** Each `placed` entry's `scale` already includes the size chart, so set `localScale` to it
(mirrored x when `flipX`). The `layout` lists give the recipe scale only: multiply by `gameScale`.

## 4. Scenes

Build each scene from `layout` (so it stays editable), and check it against `placed` and the reference PNG.

| Scene | Built from |
|---|---|
| **Farm** | `ground.farm`; the code-drawn yard and bunds; 48 plots (`layout.plots`: field, plot, grid cell, centre); house, shrine, palms, bananas, fences, buffalo, cart, dragon jar and farmer (`placed`); the recipe pieces and landmarks; the forest (`layout.forest`: id, u, v, scale, flip, **shade**, a brightness multiplier for depth); grass (`layout.grass`) and rice (`layout.rice`). |
| **Duck pen** | `ground.pen`; fences; the duck house; nest, trough and egg basket (`NEST`, `TROUGH`); Uncle Mee; ducks wander between `DUCK_SPOTS`; the recipe pieces (`PEN_LAYOUT`); grass. |
| **Market** (new) | `ground.market`; the shophouse row, stalls and lantern posts (`landmarks`); clutter (`pieces`). Auntie Daeng stands at `MARKET.daeng`, between `kit.stall_daeng_back` and `kit.stall_daeng_counter` (one Sorting Group). |
| **Village map** (new) | `ground.village`; the map-scale places (`landmarks`); trees (`pieces`); map fences; tap areas from `VILLAGE_PLACES` (grid rectangles: use polygon colliders). |

**Grass and rice:** hundreds of identical small sprites per scene. Either bake them into one sprite per scene and
season at load time (as the web game does), or keep them as separate sprites in one atlas, using Static Batching or
a single `SpriteRenderer` pass. The **hot season** swaps each grass tuft for its `_dry` version; the rice does not
change.

**Floating:** every sprite should sit **on** the ground, not above it. Each piece's pivot is its ground point, and
each casts a soft shadow (section 6). Where a sprite still looks like it floats, sink it 1–2 px into the ground,
or add a small dark contact blob under it on the `GroundCover` layer.

## 5. Game logic (port to plain C#, no MonoBehaviour)

| Web file | Holds | C# |
|---|---|---|
| `js/logic/config.js` (→ `Data/config.json`) | rules and numbers | load the JSON into a `GameConfig` ScriptableObject |
| `js/logic/state.js` | the save state, `newGame`, `sanitizeState` (repairs old saves), the seeded RNG (`mulberry`) | `GameState` (serialisable) + the same RNG, so seeded tests match |
| `js/logic/actions.js` | tools on plots (`applyTool`), planting, harvesting (`pickPlot`), selling, buying, walking, energy (`spend`) | `GameActions` |
| `js/logic/endDay.js` | the night: growth, ripening and rotting, bugs, rain, ducks laying (or starving) | `EndDay` |
| `js/logic/calendar.js` | days, months, seasons | `Calendar` |
| `js/ui/storage.js` | save and load | `JsonUtility` (or Newtonsoft) into `Application.persistentDataPath` |

The logic is pure functions over a state object, so port it 1:1 and copy the web logic tests (`tests/endDay.test.mjs`, 21 tests) into
**Unity Test Framework** EditMode tests. Get those green before building scenes.

## 6. Light, time of day and shadows (URP 2D)

| Web | Unity |
|---|---|
| Day clock from energy (`DAY`): 06:00 at full energy, 21:00 at empty | `DayClock.Hour(state)` |
| Scene tint (`daylight.json` → `hours[].tint`) | a **Global Light 2D**, colour = tint, intensity 1 |
| Sun on the normal maps (`sun`, `sunStrength`, `relief`) | a **Spot Light 2D** set very wide (or a Freeform light covering the scene) with **Normal Maps: Accurate**; aim it along `sun`; intensity = `sunStrength × relief` |
| Lamps (`layout.lamps`: x, y, radius, colour; strength = `lamps`) | **Point Light 2D** per lamp, falloff = radius, intensity ramps up with `lamps` at dusk |
| Cast shadows (`shadow.skew`, `squash`, `strength`) | the simplest match: each tall sprite gets a child shadow sprite (its own silhouette, black, alpha = `strength`), sheared by `skew` and squashed by `squash` about its pivot, on the `GroundCover` layer. Update it when the hour changes. **Shadow Caster 2D** also works, but it draws hard light-shaped shadows, not our soft ground shadows. |

The art already carries a mid-morning upper-left light, so around 09:00–15:00 the light is neutral and the scene
looks as painted.

## 7. Mobile performance targets

- **60 fps** on a mid-range phone, under about 50 batches per scene. Check with the Frame Debugger.
- **Memory:** the ground layers are the largest textures (2800 × 1200). Load each scene's atlas with Addressables
  and release it on leaving.
- **Repaint only what changes:** tapping a plot changes one plot sprite and the HUD. Nothing else should be rebuilt.
  (The web game's slowness came from rebuilding its whole light layer on every tap.)
- **UI:** use separate Canvases for the static HUD and the changing parts.

---

## 8. Suggested order

1. Project setup, sprite import, atlases, fonts (section 2).
2. Game logic in C# with tests (section 5).
3. The farm scene, static: ground, yard, sprites, grass, rice; compare with `farm_reference.png`.
4. Farm interaction: tap plots, the toolbar, seeds, crops growing, end day, HUD; save and load.
5. The duck pen, then the market and the village once their art lands.
6. The day clock, lights and shadows (section 6).
7. Sound, transitions, store builds.

## 9. Art pipeline from here

The asset agent keeps producing art in **this repo** to the same style contract (`docs/style-contract.md`): SVG
master, `_source` image, normal map and manifest stamps. After each approved batch, run
`node tools/export-unity.mjs` and copy the new or changed `Sprites/` into the Unity project. The SVGs stay the masters.
